ControlStatusNotes
HTTPSHOST-SIDEEnforced by the TLS-terminating host. HSTS is deliberately not set in app config so local HTTP dev keeps working.
Role permissionsIN PLACE3 roles with module.action permissions; every admin action fails closed.
Venue scoping (C11)IN PLACEAdmins see only allotted venues — enforced in the query layer, not the UI.
CAPTCHAPARTIALHoneypot + minimum time-on-form, server-checked. A real widget needs a site key the business hasn't issued.
Rate limitingIN PLACELogin 8/10min, sign-up 5/hr, public forms 10/hr. In-memory — needs a shared store when the app runs on more than one node.
Audit logsIN PLACE21 entries. Every auth event and admin mutation funnels through lib/audit.js.
Session timeoutIN PLACEStaff sessions 7 days, customer sessions 30, both server-validated on every request.
Password policyIN PLACEAt least 10 characters, not a common password, and not your email.
Password storageIN PLACEscrypt with a per-user random salt. No plaintext anywhere, no reversible encryption.
Security headersIN PLACECSP, X-Frame-Options, X-Content-Type-Options, Referrer-Policy, Permissions-Policy. Admin and account routes are noindex + no-store.
2FAPHASE 3Per the BRD, full 2FA is a Phase 3 item.
BackupsPARTIAL`npm run backup` snapshots the database and uploads. Scheduling it is a host-side job.
Housekeeping28 expired session row(s) can be cleared with npm run sessions:sweep. They are already invalid — expiry is checked on every request — so this is tidiness, not exposure.
